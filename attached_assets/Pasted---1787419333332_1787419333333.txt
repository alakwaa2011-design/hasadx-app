المشكلة المؤكدة
تمت إضافة تبويب «مكتبة الأنشطة» إلى شريط الهاتف، لكن الصفحة نفسها ما زالت تعرض تخطيط سطح المكتب: عمود الفلاتر الجانبي ظاهر دائماً، فيضغط منطقة النتائج والبطاقات إلى عرض ضيق وغير قابل للاستخدام. الصورة المرفقة تُظهر المشكلة بوضوح.

الهدف
إنشاء تخطيط هاتف خاص لمكتبة الأنشطة. على الهاتف تكون النتائج بعرض كامل، وتنتقل الفلاتر من العمود الجانبي إلى أدوات جوال سهلة، مع الاحتفاظ بجميع النتائج والمنطق الموجودين فعلياً.

قبل التنفيذ
	1.	حدّد ملف صفحة مكتبة الأنشطة، مكوّن الفلاتر، مكوّن بطاقات النشاط، وحالات البحث والفرز والفلترة الحالية.
	2.	حدّد جميع مجموعات الفلاتر الموجودة حالياً، مثل نوع النشاط والمادة الدراسية والمرحلة أو أي مجموعات أخرى موجودة فعلاً.
	3.	أرسل تقريراً قصيراً بهذه الملفات والحالات قبل التعديل، ثم نفّذ في المعاينة فقط.

تجربة الهاتف المطلوبة — عند عرض 390×844 وما حوله
1. رأس المكتبة والبحث
	•	يظهر عنوان واحد فقط: «مكتبة الأنشطة» مع أيقونة المكتبة الحالية.
	•	يظهر حقل البحث بعرض المحتوى كاملاً تحت العنوان.
	•	لا تكرر بطاقة أو عنواناً ثانياً باسم المكتبة في أول الصفحة إذا كان لا يضيف وظيفة.

2. شريط التحكم المختصر
تحت البحث مباشرة، ضع صفاً واحداً واضحاً يحتوي:

	•	زر «تصفية» مع أيقونة الفلتر وعدّاد صغير لعدد الفلاتر الفعالة، إذا وُجدت.
	•	زر الفرز الحالي، مثل «الأكثر استخداماً»، يعيد استخدام منطق الفرز القائم.
	•	لا تجعل النصوص طويلة أو أزراراً ضيقة؛ حافظ على هدف لمس لا يقل عن 44px.

3. الفلاتر على الهاتف
	•	أخفِ عمود الفلاتر الجانبي كلياً على الهاتف. لا تتركه بجانب النتائج ولا كعمود قابل للتمرير.
	•	عند الضغط على «تصفية»، افتح Bottom Sheet / Drawer مناسباً لـRTL من أسفل الشاشة أو جانبها، باستخدام المكوّن الموجود في المشروع إن وُجد.
	•	داخل النافذة، اعرض الفلاتر الموجودة فعلياً فقط، مرتبة في مجموعات واضحة. مثال ترتيب إذا كانت هذه الفلاتر موجودة: نوع النشاط، ثم المادة الدراسية، ثم أي فلاتر إضافية.
	•	استخدم Chips أو خيارات قابلة للمس داخل النافذة، مع إظهار الاختيار الحالي بوضوح.
	•	أضف زرين في النهاية:
	◦	«عرض النتائج»: يطبّق الاختيارات أو يؤكد الحالة الحالية ويغلق النافذة.
	◦	«إعادة ضبط»: يعيد استخدام منطق مسح الفلاتر الحالي.
	•	يجب أن يبقى البحث والفرز والفلترة مرتبطين بالحالة والمنطق الحاليين؛ لا تنشئ استعلامات أو API أو نسخة ثانية من الفلاتر.

4. نتائج الأنشطة وبطاقاتها
	•	اجعل منطقة النتائج بعرض الهاتف المتاح كاملاً، في عمود واحد واضح.
	•	لا تظهر بطاقة نصف مقصوصة أو نصاً خارج الشاشة أو محتوى خلف شريط الهاتف السفلي.
	•	احتفظ بالبيانات الحقيقية للبطاقة: العنوان، النوع، المادة، الاستخدام، والزر أو الإجراء الموجود فعلياً. لا تنشئ أرقاماً أو أنشطة تجريبية.
	•	إذا وُجد قسم «رائج الآن»، يمكن إبقاؤه كتمرير أفقي للبطاقات أو في تخطيط متجاوب واضح، لكن لا تسمح له بضغط النتائج أو تغطيتها.

5. سطح المكتب
	•	أبقِ تصميم مكتبة الأنشطة على سطح المكتب كما هو: عمود الفلاتر الجانبي والنتائج لا تتغيران بصرياً أو وظيفياً.

قيود صارمة
	•	لا تغيّر مسار مكتبة الأنشطة أو شريط التنقل الذي أُضيف حديثاً.
	•	لا تغيّر قواعد رؤية الأنشطة أو نشرها أو استيرادها أو ملكيتها.
	•	لا تغيّر نتائج البحث أو الفلترة أو الفرز أو مصادر البيانات أو API أو قاعدة البيانات.
	•	لا تغيّر الألعاب أو الأنشطة أو الباقات أو النقاط أو الدفع أو Lemon Squeezy أو CreditService أو الأسرار أو GA4 أو Meta Pixel.
	•	لا تستخدم بيانات مصطنعة أو بطاقات وهمية أو شعارات أو صور جديدة.
	•	لا تنشر.

التحقق المطلوب
	1.	لقطة 390×844 لصفحة مكتبة الأنشطة تُظهر: العنوان، البحث، زر التصفية، زر الفرز، وبطاقات النتائج بعرض واضح دون عمود جانبي.
	2.	لقطة للـBottom Sheet مفتوحاً تُظهر مجموعات الفلاتر الحالية وزري «عرض النتائج» و«إعادة ضبط».
	3.	اختبار فعلي للبحث، اختيار فلتر واحد، إعادة ضبط، وتغيير الفرز؛ يجب أن تعطي جميعها السلوك الموجود نفسه قبل التعديل.
	4.	تحقق من عدم وجود تمرير أفقي، وعدم حجب آخر بطاقة خلف شريط التنقل السفلي، وعدم تكرار العنوان.
	5.	لقطة سطح مكتب تؤكد بقاء العمود الجانبي والتخطيط الحاليين كما هما.
	6.	شغّل TypeScript وBuild والاختبارات ذات الصلة إن وجدت.

التقرير المطلوب
أرسل سبب المشكلة، الملفات المعدلة، الفلاتر الفعلية التي ظهرت في واجهة الهاتف، نتائج الاختبارات، ولقطات: هاتف قبل/بعد، وBottom Sheet، وسطح المكتب. لا تنشر؛ انتظر المراجعة.
