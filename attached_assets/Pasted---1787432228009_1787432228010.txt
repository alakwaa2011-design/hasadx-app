الهدف

عند اختيار المعلم حزمة نقاط أو باقة من النافذة الداخلية لنقص رصيد الذكاء الاصطناعي، لا تفتح صفحة أو تبويب Checkout جديداً. استخدم Lemon Squeezy Checkout Overlay الرسمي ليظهر الدفع كطبقة فوق صفحة حصاد الحالية.

هذا الهدف يخص شكل فتح Checkout فقط. لا تغيّر أي من منطق الدفع أو المنتجات أو الباقات أو الأرصدة.

ما يجب الحفاظ عليه

•
منتجات Lemon Squeezy، Variant IDs، الأسعار، كوبونات الخصم، Checkout URLs، return URLs، Webhooks، وPayment Intents كما هي حرفياً.

•
CreditService ومنطق الخصم والاسترداد وhold/capture/refund كما هي.

•
لا تُنشئ Checkout URL أو Intent جديداً لمجرد فتح نافذة نقص الرصيد أو اختيار بطاقة؛ استمر في استخدام اللحظة والمنطق الحاليين لإنشاء URL النهائي فقط.

•
لا تغيّر Lemon Squeezy Store أو إعدادات الـDashboard أو تنشر من Lemon.

قبل التنفيذ

1.
حدّد المسار الحالي الذي ينشئ أو يعيد Checkout URL لحزم نقاط حصاد والباقات.

2.
حدّد أين يحدث الانتقال الحالي إلى نافذة أو صفحة Checkout جديدة.

3.
تحقق من عدم وجود تحميل سابق لـLemon.js أو Checkout Overlay في الواجهة، ومن أن إضافة السكربت لن تتكرر في SPA.

4.
أرسل تقريراً قصيراً بالملفات ونقاط الربط قبل التعديل، ثم نفّذ في المعاينة فقط.

التدفق المطلوب

1.
تظهر نافذة نقص الرصيد الداخلية الحالية.

2.
يختار المعلم «شراء نقاط» أو «عرض الباقات»، ثم يختار بطاقة فعلية.

3.
عند الضغط على «المتابعة إلى الدفع الآمن» فقط، يطلب التطبيق Checkout URL الحالي من المسار/المعالج القائم.

4.
عند استلام URL الصحيح، افتحه داخل Lemon Squeezy Overlay الرسمي باستخدام Lemon.js، وليس عبر window.open أو location.href أو iframe مكتوب يدوياً.

5.
تبقى صفحة حصاد خلف طبقة الدفع. أخفِ أو عطّل النافذة الداخلية الخاصة باختيار الحزم أثناء فتح Overlay لتجنب تراكب نافذتين وتعارض التركيز.

6.
عند إغلاق Overlay من دون نجاح، يعود المعلم بأمان إلى شاشة اختيار الحزمة أو نافذة نقص الرصيد دون إنشاء خصم أو Checkout إضافي.

7.
عند حدث Checkout.Success، لا تمنح رصيداً من المتصفح. اعرض فقط حالة نجاح مؤقتة وحدّث الرصيد من الخادم بالطريقة الحالية؛ ويبقى الاعتماد النهائي على الخادم وWebhook وحالة الشراء القائمة.

استخدام Lemon.js

•
حمّل مكتبة Lemon.js الرسمية مرة واحدة فقط في الواجهة، وفق الوثائق الرسمية:
https://app.lemonsqueezy.com/js/lemon.js

•
في React/SPA، تأكد من تهيئة Lemon.js بعد mount بالطريقة الرسمية إن لزم، من دون تحميل مكرر أو تسريب event handlers.

•
افتح URL النهائي عبر API الرسمية للمكتبة (مثل LemonSqueezy.Url.Open(checkoutUrl )) أو class الرسمية المعتمدة، ولا تنشئ طبقة مزيفة أو iframe يدوي.

•
اربط handler واحداً فقط للأحداث، واعتبر Checkout.Success إشارة واجهة لا بديلاً للتحقق الخادمي.

تجربة المستخدم

•
عنوان زر التأكيد يبقى: «المتابعة إلى الدفع الآمن».

•
أظهر حالة تحميل قصيرة ومقيدة أثناء طلب URL وفتح Overlay، مع منع النقر المزدوج.

•
إن تعذر تحميل Lemon.js أو فتح Overlay، أظهر رسالة خطأ مفهومة مع زر إعادة المحاولة. لا تفتح صفحة جديدة تلقائياً كبديل صامت.

•
اجعل الصفحة الأساسية وواجهة الحزم RTL كما هي؛ Overlay نفسه واجهة Lemon Squeezy المضبوطة من لوحة Lemon.

قيود صارمة

•
لا تغيّر API أو قاعدة البيانات أو migrations أو الأسرار.

•
لا تغيّر الدفع المباشر أو Lemon Squeezy أو Webhooks أو المنتجات أو الأسعار أو الباقات أو CreditService.

•
لا تضف بيانات اختبار دائمة ولا تكمل أي عملية دفع حيّة.

•
لا تغيّر التسجيل أو المصادقة أو الألعاب أو مكتبة الأنشطة أو GA4 أو Meta Pixel.

•
لا تنشر.

التحقق المطلوب

1.
من نافذة نقص الرصيد، الوصول إلى بطاقة حزمة ثم «المتابعة إلى الدفع الآمن» يفتح Overlay فوق الصفحة ولا يغير URL صفحة حصاد ولا يفتح تبويباً جديداً.

2.
اختبار حزمة نقاط وباقة اشتراك باستخدام URLs أو mocks آمنة غير حيّة؛ لا تنفذ دفعاً حقيقياً.

3.
إغلاق Overlay يعيد المستخدم إلى نقطة سليمة بلا خصم وبلا Intent/Checkout إضافي.

4.
محاكاة Checkout.Success: تحديث الرصيد من المصدر الخادمي فقط، وعدم منح أي رصيد مباشرة من الحدث في المتصفح.

5.
اختبار فشل تحميل المكتبة أو فشل Checkout URL: تظهر رسالة قابلة لإعادة المحاولة، ولا يحدث انتقال صامت لصفحة خارجية.

6.
اختبار النقر المزدوج: لا يفتح أكثر من Overlay ولا ينشئ أكثر من Checkout/Intent.

7.
فحص على 390×844 و1440×900، مع TypeScript وBuild والاختبارات المناسبة.

التقرير المطلوب

أرسل: الملفات المعدلة، معالج URL الحالي المعاد استخدامه، أسلوب تحميل Lemon.js ومنع تكراره، نتائج اختبارات فتح/إغلاق/نجاح Overlay، ولقطات للنافذة الداخلية ثم Overlay على الهاتف وسطح المكتب. لا تنشر؛ انتظر المراجعة.
