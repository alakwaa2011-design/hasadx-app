التقرير الكامل: خطة تنفيذ ميزة «المتشابهات» في مصحف حصاد
قبل البدء، بحثت في مصادر بيانات القرآن الموثوقة المتاحة لأن المتشابهات (الآيات/العبارات التي تتشابه في اللفظ بين مواضع مختلفة وتُشكّل تحديًا للحفظة) لا تتوفر في Quran Foundation Content API v4 الذي نستخدمه حاليًا للتجويد والتفسير والصوت. لذلك هذا مشروع بحجم مختلف يتطلب مصدر بيانات جديدًا بالكامل.

1) مصدر البيانات (الأهم والأكثر حساسية)
وجدت مصدرًا موثوقًا ومُدارًا رسميًا: QUL — Quranic Universal Library (qul.tarteel.ai)، وهو مشروع Tarteel AI المعروف والمُستخدم من عشرات تطبيقات القرآن. يوفر مجموعتي بيانات جاهزتين للتنزيل (JSON):

المجموعة	المحتوى	الحجم
Mutashabihat ul Quran
عبارات مشتركة بين آيات (phrases.json + phrase_verses.json) مع مدى الكلمات الدقيق لكل عبارة في كل آية
٥٬٢٧٧ سجل
Similar Ayahs
آيات متشابهة في اللفظ/السياق/المعنى
٤٬٠٠١ آية
لا يوجد REST API رسمي منها بعد (أعلنوا أنه "قيد التطوير")، لذا سأتعامل معها كـ بيانات ساكنة يتم تنزيلها مرة واحدة وتضمينها في الخادم — تمامًا بنفس أسلوب qcf-v2-page-integrity.json الموجود حاليًا في المشروع، وليس عبر استدعاء API حي لكل طلب.

قبل أي تنزيل، سأتحقق من رخصة الاستخدام/إعادة التوزيع المذكورة على صفحة QUL ولن أضمّن البيانات إن كانت الرخصة تمنع ذلك تجاريًا — هذا قرار لا أستطيع تجاوزه بدون التأكد الصريح من الشروط.

2) خطة الخادم (Backend)
سكربت تنزيل/تطبيع لمرة واحدة (scripts/build-mutashabihat-data.ts): يجلب phrases.json وphrase_verses.json، يتحقق من سلامتها (hash/عدّ السجلات، كما فعلنا مع صفحات المصحف)، ويولّد ملف JSON مضغوط مبني حسب surah:ayah لسرعة البحث (لا تخمين ولا توليد نصوص — فقط تنظيف بنية البيانات الأصلية).
مخطط OpenAPI جديد: مسار GET /quran/mutashabihat/verse/{surahNumber}/{ayahNumber} يُعيد:
قائمة العبارات المتشابهة الموجودة في هذه الآية (نص العبارة + مدى الكلمات لتظليلها).
لكل عبارة: قائمة الآيات الأخرى التي تحوي نفس العبارة (رقم السورة/الآية + نص الآية + مدى الكلمات فيها أيضًا لتظليل الفروق).
تخزين مؤقت وحدود معدل الطلبات: نفس نمط TAJWEED_CACHE_MS وpublicQuranTajweedLimiter (تخزين ٢٤ ساعة، ومحدد معدل عام لأن البيانات ساكنة أصلاً).
Orval codegen: توليد useGetQuranMutashabihatVerse تلقائيًا مثل الخطاف السابق.
اختبارات الخادم: تحليل البيانات، حالات عدم وجود تشابه (مصفوفة فارغة وليس تخمينًا)، أرقام غير صالحة، تخزين مؤقت.
3) خطة الواجهة الأمامية (Frontend)
نقطة الدخول
سأضيف زر «المتشابهات» إلى QuranAyahActionSurface (شريط إجراءات الآية الحالي الذي يحوي: تشغيل، نسخ، حفظ، تفسير) — لأن التشابه غالبًا على مستوى الآية/العبارة كاملة وليس كلمة مفردة، بعكس التجويد. سيظهر الزر فقط إذا كانت الآية موجودة فعليًا في بيانات QUL (نفس مبدأ عدم التخمين المُتبع في زر التجويد).

البطاقة عند الضغط
مكوّن جديد quran-mutashabihat-card.tsx (بطاقة سفلية متجاوبة، بنفس نمط quran-tajweed-rule-card.tsx):

عرض الآية الحالية مع تظليل العبارة المشتركة داخل النص.
قائمة بالمواضع الأخرى في القرآن حيث ترد نفس العبارة، كل موضع يعرض:
السورة والآية (رقمًا واسمًا).
نص الآية الكاملة مع تظليل موضع العبارة فيها — وتمييز الكلمات المختلفة عن الأصل بلون آخر إن كانت هناك اختلافات طفيفة (هذا هو جوهر فائدة الميزة للحفظة).
زر «انتقال» للقفز مباشرة لتلك الآية في المصحف.
زر استماع صوتي لكل موضع (إعادة استخدام useQuranWordAudio/الصوت الحالي للآية عبر القارئ الافتراضي).
عداد إجمالي: "توجد ٣ مواضع أخرى مشابهة لهذه الآية".
إتاحة الوصول (Accessibility)
نفس المعايير المطبّقة سابقًا: RTL، role="dialog", aria-modal, إغلاق بـ Escape، تركيز تلقائي، تباين ألوان كافٍ للتظليل.

4) قرارات تحتاج تأكيدك قبل البدء
أحتاج إجاباتك على النقاط التالية لأن كل واحدة تغيّر حجم العمل والتصميم:

أي مجموعتي بيانات QUL تريد اعتمادها في هذه المرحلة الأولى؟

كلتا المجموعتين معًا: العبارات الدقيقة + الآيات المتشابهة عمومًا
أين يظهر زر «المتشابهات»؟

ضمن إجراءات الآية الحالية (مع التشغيل/النسخ/الحفظ/التفسير) — موصى به
هل تريد إضافة وضع اختبار تفاعلي (مثلاً: اعرض آيتين متشابهتين واطلب من الطالب تحديد الفرق) مع الميزة الأساسية، أم عرض معلوماتي فقط للآن؟

عرض معلوماتي فقط الآن (أبسط وأسرع — موصى به)، ويمكن إضافة وضع اختبار لاحقًا
بناءً على اختياراتك، إليك الخطة النهائية المحدّثة:

الخطة النهائية المعتمدة
نطاق البيانات: سأدمج مجموعتي بيانات QUL معًا:

phrases.json + phrase_verses.json (العبارات الدقيقة مع مدى الكلمات) → لتظليل الفرق بدقة كلمة بكلمة.
Similar Ayahs (٤٬٠٠١ آية) → لتغطية أوسع للآيات المتشابهة عمومًا حتى لو لم تكن ضمن قاعدة العبارات الدقيقة. عند عرض النتائج سأميّز المصدر ضمنيًا (عبارة مطابقة بدقة ذات مدى كلمات محدد، مقابل تشابه عام بمستوى الآية) حتى لا يُختلط الأمر على المستخدم ولا نبدو كأننا نساوي بين مستويين مختلفين من الدقة.
نقطة الدخول: زر «المتشابهات» ضمن QuranAyahActionSurface (شريط إجراءات الآية) بجانب تشغيل/نسخ/حفظ/تفسير — يظهر فقط عند وجود بيانات فعلية لهذه الآية.

المحتوى: عرض معلوماتي فقط في هذه المرحلة (بدون اختبار تفاعلي)، مع تصميم الكود بحيث يسهل إضافة وضع اختبار لاحقًا دون إعادة هيكلة.

خطوات التنفيذ بالترتيب
التحقق من رخصة بيانات QUL قبل التنزيل والتضمين.
تنزيل ومعالجة phrases.json + phrase_verses.json + Similar Ayahs، وبناء سكربت تطبيع + ملف بيانات ساكن مضمّن في الخادم مع تحقق من سلامته (hash/عدّ).
إضافة مخطط OpenAPI ومسار GET /quran/mutashabihat/verse/{surahNumber}/{ayahNumber} مع تخزين مؤقت ومحدد معدل.
تشغيل orval codegen لتوليد الخطاف useGetQuranMutashabihatVerse.
اختبارات الخادم (تحليل، حالات فارغة، أرقام غير صالحة).
زر «المتشابهات» في QuranAyahActionSurface + بطاقة quran-mutashabihat-card.tsx بنفس نمط بطاقة التجويد (تظليل العبارة، تمييز الاختلافات، انتقال، صوت).
اختبارات واجهة أمامية (ظهور/إخفاء الزر، التنقل بين المواضع، الوصولية).
تشغيل الفحوص والاختبارات والبناء الكامل، ثم تنبيهك أن التغييرات جاهزة لكن تحتاج إعادة نشر الخادم يدويًا (كما حدث مع التجويد) لتظهر فعليًا في الموقع المباشر.
