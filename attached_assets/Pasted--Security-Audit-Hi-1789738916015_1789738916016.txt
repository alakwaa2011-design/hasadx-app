قرأت تقرير Security Audit. أريد الآن تنفيذ المرحلة الأولى فقط من الإصلاحات الأمنية عالية الخطورة (High)، بدون أي إعادة تصميم للنظام وبدون تغيير سلوك المستخدم الحالي.

ابدأ بهذه النقاط فقط:

1. إصلاح SSRF في /shorten بشكل كامل، مع منع الوصول إلى localhost وloopback وprivate/link-local IPs وmetadata endpoints، والتحقق من DNS والـredirects لمنع تجاوز الحماية.

2. تقوية OTP:
- استبدال Math.random بمولد آمن من Node crypto.
- عدم تخزين OTP كنص واضح؛ خزّن hash آمنًا منه.
- إضافة حد لمحاولات التحقق مرتبط بالحساب/OTP وليس IP فقط، مع إبطال الرمز أو قفل مؤقت بعد عدد مناسب من المحاولات.
- اجعل صلاحية OTP الفعلية 10 دقائق لتطابق الرسالة الحالية.
- حافظ على تجربة إرسال وإعادة إرسال OTP الحالية وعدم كسر تسجيل الدخول أو إنشاء الحساب.

3. إصلاح مخاطر رفع الملفات:
- منع SVG وHTML وXML وJavaScript وأي نوع active content من جميع مسارات المرفقات التي لا تحتاجها.
- لا تعتمد فقط على MIME type أو حجم الملف الذي يرسله العميل.
- أضف server-side/post-upload verification للنوع والحجم الحقيقيين بطريقة مناسبة للـdirect uploads الحالية.
- لا تكسر رفع الصور وPDF وملفات Word/Excel والملفات المستخدمة حاليًا في حصاد.

4. إصلاح Session Fixation عن طريق تدوير Session ID بعد نجاح المصادقة باستخدام الطريقة الصحيحة في express-session، مع الحفاظ على teacherId والبيانات المطلوبة في الجلسة الجديدة.

شروط مهمة جدًا:

- لا تعدّل Lemon Squeezy أو منطق الاشتراكات أو الأرصدة أو webhooks في هذه المرحلة.
- لا تغيّر Database schema إلا إذا كان ضروريًا فعلًا لإصلاح OTP attempt tracking؛ وإذا احتاج migration فاشرحه قبل التنفيذ.
- لا تستخدم npm audit fix --force.
- لا تحدّث dependencies الآن.
- لا تغيّر CORS أو CSRF أو بقية نقاط Medium/Low الآن.
- لا تغيّر واجهات المستخدم أو routes أو API contracts إلا بالحد الأدنى الضروري.
- حافظ على التوافق مع الحسابات والجلسات والـOTP الموجودة حاليًا قدر الإمكان.

بعد التنفيذ شغّل الاختبارات والفحوص المناسبة، واختبر خصوصًا:
signup → OTP → login → logout → login مرة أخرى
إعادة إرسال OTP
OTP خاطئ ومتكرر
انتهاء OTP
password reset
رفع الأنواع المسموحة والممنوعة

بعد الانتهاء توقف ولا تنتقل للمرحلة التالية.

أعطني تقريرًا يوضح:
- الملفات التي تغيرت.
- ماذا تغير في كل ملف.
- أي migration تمت إضافته.
- نتائج الاختبارات.
- هل ظهرت regressions أو تغييرات في السلوك الحالي.
- وما تبقى من تقرير Security Audit دون إصلاح.
