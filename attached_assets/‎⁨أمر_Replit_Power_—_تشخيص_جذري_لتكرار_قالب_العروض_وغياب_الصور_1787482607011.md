# أمر Replit Power — تشخيص جذري لتكرار قالب العروض وغياب الصور

## المشكلة المؤكدة

مولّد العروض في منصة حصاد تم توجيهه سابقاً إلى التنويع مرات كثيرة، لكنه ما زال ينتج عروضاً متشابهة: تخطيط متكرر، خطوط وتنسيق محدودان، صور أو وسائط بصرية غائبة، وتبدّل الموضوع لا يؤدي إلى تبدّل بصري حقيقي.

لا أريد جولة أخرى من تعديل Prompt لفظي مثل «اجعل العرض إبداعياً». أريد كشف **المصدر التقني** الذي يفرض هذا التكرار، ثم تقريراً دقيقاً قبل تنفيذ أي تغيير.

## وضع التنفيذ

استخدم **Power** في وضع تشخيص وقراءة فقط. لا تعدّل كوداً، لا تنشئ عرضاً جديداً، لا تستدعي مولد الذكاء الاصطناعي، لا تخصم نقاطاً، لا تنشئ ملفات مستخدم أو بيانات اختبار، ولا تنشر.

## حدود صارمة

لا تلمس:

- نقاط حصاد أو CreditService أو تسعير أدوات الذكاء أو الدفع أو Lemon Squeezy.
- قاعدة البيانات أو migrations أو الأسرار أو Webhooks.
- منطق العروض التفاعلية الحالي، بيانات المستخدمين، الروابط، أو آليات المشاركة.
- ملفات غير مرتبطة مباشرة بتوليد العرض أو رندره.

## المطلوب من الفحص

### 1. خريطة المسار الفعلي

حدّد بالمسارات والأسماء:

1. واجهة إنشاء العرض.
2. الخادم أو الإجراء الذي يطلب المحتوى من الذكاء الاصطناعي.
3. Prompt أو Schema أو JSON contract الذي يحدد هيكل الشرائح.
4. أي كود يختار template أو layout أو لون أو خط أو slide type.
5. renderer الذي يحول الشرائح إلى واجهة مرئية.
6. مسار جلب الصور أو توليدها أو استبعادها، إن وجد.
7. أي fallback يجعل جميع الشرائح تستعمل نفس التخطيط.

ارسم تدفقاً مختصراً من إدخال موضوع العرض حتى ظهور الشريحة النهائية، واذكر الملفات المتورطة فقط.

### 2. إثبات سبب التكرار

ابحث تحديداً عن واحد أو أكثر من هذه الأسباب، وقدّم الدليل من الكود لا التخمين:

| احتمال الخلل | ما يجب التحقق منه |
|---|---|
| قالب واحد | هل renderer يملك مكوّناً أو CSS ثابتاً لكل الشرائح؟ |
| Schema فقير | هل يطلب النموذج عنواناً ونقاطاً فقط بلا نوع شريحة أو اتجاه بصري أو خطة وسائط؟ |
| اختيار تصميم صوري | هل اختيار template لا يعتمد على الموضوع أو المستوى أو نوع المحتوى؟ |
| صور غير موصولة | هل يوجد image plan لكن لا تُجلب الصور أو لا تمر إلى renderer؟ |
| fallback صامت | هل يفشل جلب الصور أو parse المحتوى ثم يعود تلقائياً لتخطيط نصي موحّد؟ |
| تقييد renderer | هل يدعم renderer عدداً محدوداً من الأنواع مهما تغيّر الناتج؟ |

### 3. مراجعة أمثلة سابقة دون توليد جديد

إن كانت هناك عروض موجودة فعلياً أو fixtures أو لقطات معاينة متاحة، قارِن ثلاثة موضوعات مختلفة في بنيتها المخزنة أو مخرجاتها فقط، من دون إنشاء محتوى جديد. أثبت هل كل الشرائح تستعمل النوع نفسه أو props نفسها أو بنية متشابهة.

### 4. خطة إصلاح بنيوية مقترحة — لا تنفذها

اكتب خطة تغيير محددة للملفات، لا تقتصر على تعديل Prompt. يجب أن تعالج النقاط التالية إذا أكدها الفحص:

1. **Design brief** مستقل لكل عرض، يحدد اتجاهه البصري بحسب الموضوع والمرحلة التعليمية والهدف.
2. **Slide types** حقيقية ومتعددة، مثل: افتتاح بصري، مفهوم، مقارنة، تسلسل/عملية، خط زمني، مخطط، مثال تطبيقي، سؤال تفاعلي، خلاصة. لا تُستخدم كلها إلزامياً؛ تختار بحسب المحتوى.
3. **Image plan** قابل للتنفيذ لكل شريحة تحتاج وسائط، مع مصدر وأسلوب احتياطي واضح عند عدم توفر صورة مناسبة.
4. اختيار من عائلات تصميم متباينة بالفعل، لا تغيير لون القالب نفسه فقط.
5. renderer يدعم أنواع الشرائح والوسائط والخطوط والتباين، بدلاً من تحويل جميع الشرائح إلى بطاقة نصية واحدة.
6. حواجز جودة تمنع قبول عرض مكوّن بالكامل من شرائح نصية متشابهة عند طلب موضوع بصري مناسب.

## مخرجات التقرير المطلوبة

أرسل تقريراً من الأقسام التالية فقط:

1. **السبب الجذري المؤكد** مع الأدلة.
2. **الملفات والمسارات المعنية**.
3. **ما الذي تم تنفيذه سابقاً ولماذا لم يعالج المشكلة**.
4. **خطة إصلاح بنيوية مقترحة** مرتبة حسب الأولوية والمخاطر.
5. **ما الذي يحتاج قرار مروان قبل تنفيذه**، خصوصاً مصادر الوسائط أو أي تكلفة ذكاء اصطناعي محتملة.

لا تنفذ أي تعديل ولا تنشر. انتظر التقرير لمراجعته أولاً.
